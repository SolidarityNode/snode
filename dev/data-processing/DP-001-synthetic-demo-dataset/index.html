    DP-001: Synthetic demo dataset¶

    Field Value
    Status done
    Author SolidarityNode contributors
    Date 2026-11-24
    Municipality / study area fictional municipalities M-A (core) and M-B (buffer)
    Used in data package demo-synthetic 0.1.0 (data/synthetic/demo/); tests and UAT only, no paper
    QGIS version not used (generated by script); the GeoPackage opens in QGIS 3.x
    Reproducible file scripts/generate_demo_data.py

    Purpose¶

    A small, fully synthetic study area for automated tests and manual UAT: loading, joins, shortest-path checks against known answers, cross-border effects and a disruption overlay. Not used in any paper. Every value is a placeholder.

    Sources¶

    Source Version / download date Licence File in data/local/
    none: all values invented in scripts/generate_demo_data.py generator as committed AGPL-3.0-or-later (repository) none (output is committed under data/synthetic/demo/)

    Coordinate reference system¶

    Output in EPSG:2100 (GGRS87 / Greek Grid), the CRS planned for the first application, so the same tooling is exercised. The grid origin (130000, 3880000) lies in open sea (about 35° N, 20° E) so that no real place is implied. No reprojection.

    Steps¶

    1. Generate all layers and tables: 
      python3 scripts/generate_demo_data.py
      The script writes the GeoPackage with the standard-library sqlite3 module (GeoPackage 1.4 tables and geometry encoding), the CSV tables, the scenario JSON, the hand-check table (Dijkstra over the edge list, per mode, baseline and with edge E02 closed) and manifest.json with SHA-256 checksums.
    2. Manual edits: none.

    Output¶

    File in data/synthetic/demo/ Layers / tables Feature count Key fields
    demo.gpkg municipalities 2 municipality_id, role
    demo.gpkg spatial_units 8 (6 core, 2 buffer) unit_id, municipality_id, role
    demo.gpkg unit_centroids 8 unit_id, node_id
    demo.gpkg facilities 4 (1 in buffer) facility_id, node_id, role
    groups.csv, population.csv groups, population 3 groups, 24 rows group_id, unit_id
    services.csv, facility_services.csv services, capacity inputs 2, 6 rows service_id, facility_id
    network_nodes.csv, network_edges.csv network 12 nodes, 13 edges × 2 modes node_id, edge_id, mode
    hand_check_travel_times.csv expected travel times 128 rows (2 scenarios × 2 modes × 8 units × 4 facilities) scenario_id, mode, unit_id, facility_id
    scenarios/C-DEMO-REF.json scenario 1 id

    Checks¶

    • [x] CRS is the expected one: GDAL (pyogrio) reports EPSG:2100 for all four layers.
    • [x] Feature counts: 2 municipalities, 8 units, 8 centroids, 4 facilities.
    • [x] Geometry validity: all polygons valid (Shapely is_valid), each unit 4 km².
    • [x] Visual check: not applicable (open sea by design).
    • [x] Spot checks: worked examples in data/synthetic/demo/README.md; core/tests/test_demo_dataset.py recomputes every hand-check time from the edge list and verifies the manifest checksums.
    • [x] Running the generator twice gives byte-identical files.

    Assumptions and limitations¶

    • Uniform placeholder speeds (walking 12 min/km, car 2 min/km); the same edges for both modes.
    • Unit centroids are the square centres; edge E13 is longer than the straight line between its nodes by design (a winding road).
    • The buffer is the whole neighbouring municipality for this demo only; the buffer rule is open (OQ-28).
    • Rationing uniform in the scenario is a placeholder required by the model (OQ-24).

    Open issues¶

    • The manifest follows the draft format of ADR 0013 (Proposed); update it when that ADR is decided.
